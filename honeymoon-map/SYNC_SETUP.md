# PC와 휴대폰 공유 연결

배포 환경에서 한 번만 설정하면 됩니다. Supabase 계정이나 별도 데이터베이스는 필요하지 않습니다.

1. Vercel에서 `kw-honeymoon` 프로젝트를 엽니다.
2. **Storage → Create Database / Create Storage → Blob**을 선택합니다.
3. 접근 방식은 반드시 **Private**을 선택합니다. 저장소 이름은 `honeymoon-shared`처럼 지정합니다.
4. 이 프로젝트의 **Production** 환경에 연결합니다. `BLOB_READ_WRITE_TOKEN` 환경변수가 자동 추가되는지 확인합니다. 변수 이름의 접두사는 기본값으로 둡니다.
5. 수정 코드의 배포가 이미 끝났다면 **Deployments → 최신 배포 → Redeploy**를 실행하여 환경변수를 반영합니다.
6. 기존 데이터가 있는 **PC에서 먼저** 사이트를 새로고침하고, 상단의 **PC · 휴대폰 함께 보기**에서 **기존 첨부 암호**를 입력합니다.
7. **공유 완료**가 표시될 때까지 기다립니다. 처음에는 PC에 저장된 첨부파일을 전송하므로 시간이 걸릴 수 있습니다.
8. 휴대폰에서도 같은 주소를 열어 같은 암호를 입력합니다. 이후 예약 체크·메모·사용자 체크리스트·첨부파일 목록은 자동 반영됩니다. 화면을 열어 둔 경우 5초 간격으로 확인하고, 다시 화면으로 돌아오면 즉시 확인합니다. 파일 전송 시간은 크기와 연결 속도에 따라 다릅니다.

비공개 저장소와 [Vercel 공식 설정 안내](https://vercel.com/docs/vercel-blob/using-blob-sdk)에 따라 토큰은 서버에서만 사용합니다. 토큰이나 암호를 Git 또는 채팅에 올릴 필요가 없습니다. 저장소 요금과 사용량은 Vercel 대시보드에서 확인합니다.

## 데이터 보관 방식

- 공용 데이터는 `honeymoon/shared-v1.json`, 첨부 원본은 `honeymoon/files/`에 저장합니다.
- 서버가 기존 암호화 첨부의 암호를 검증하고, 서명된 HttpOnly 쿠키로 이 기기의 연결을 유지합니다.
- 새 첨부는 원본이 공용 저장소에 저장된 뒤 목록에 반영됩니다. 전송 실패 시 이 기기에 남고 자동으로 재시도합니다.
- 기존 기기의 데이터는 공용 저장소에 아직 없는 항목만 추가합니다. 공용 저장소의 최신 값과 삭제 표시를 예전 데이터로 덮어쓰지 않습니다. PC를 먼저 연결하면 기존 PC 값이 먼저 공유됩니다.
- 서로 다른 예약·필드·체크리스트 항목·첨부는 각각 병합합니다. 같은 필드를 두 기기에서 바꾸면 서버에 마지막으로 저장된 값이 적용됩니다. 오프라인에서 수정한 값도 재연결 후 저장됩니다.
- 저장 요청에는 고유 ID를 붙이고, ETag 조건부 저장으로 동시 쓰기를 재시도합니다. 응답을 받지 못한 요청을 재전송해도 이미 처리한 작업은 중복 적용하지 않습니다.
- 첨부는 기기에 내려받아 오프라인에서도 열 수 있게 캐시합니다. 처음 내려받지 못한 파일은 인터넷이 필요합니다.
- 파일 한도는 25MB입니다. 기존 파일이 더 크면 작은 파일로 다시 첨부해 주세요.
- 앱에서 첨부를 삭제하면 모든 기기의 목록에서 삭제됩니다. 공용 저장소의 원본은 보관되며 자동으로 영구 삭제하지 않습니다.
- **공유 연결 끊기**는 서버 연결을 끊습니다. 이미 기기에 저장된 예약 상태와 파일 캐시는 남아 있습니다.
- 백업 가져오기로 변경한 내용도 공유됩니다. 환율·지도 캐시·화면 배치·완벽 가이드의 체크는 기기별 설정입니다.

## 별도 공유 암호를 쓰려면

Vercel의 **Settings → Environment Variables**에 서버 전용 `HONEYMOON_SYNC_PASSWORD`를 추가하고 다시 배포합니다. 설정하지 않으면 기존 첨부 암호를 사용합니다. 별도 공유 암호를 설정한 경우 기존 내장 티켓의 잠금은 기존 첨부 암호로 풀어야 합니다.

## 개발 검증

`npm test`는 동시 최초 생성·ETag 충돌·중복 재시도·이전 기기 데이터 병합·삭제 표시·오프라인 복구·첨부 다운로드·서명 세션을 검증합니다. 저장소는 테스트용 메모리 구현을 사용합니다.

`npm run build`는 프런트엔드와 Vercel API의 TypeScript 검사를 함께 수행합니다. 실제 저장소 전송과 두 기기의 표시 확인은 위 연결 설정 후 진행합니다. `npm run dev`에는 Vercel API가 없으므로 서버까지 로컬에서 확인하려면 `vercel dev`를 사용합니다.
